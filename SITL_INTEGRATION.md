# SITL и сохранённая аппаратная интеграция

`mavlink_bridge.py` и `real_mission.py` сохранены. Новый FastAPI/React/EDGE-контур работает только с локальной симуляцией и не отправляет аппаратные команды. Автопилоты и SITL-процессы в этой среде не были подключены; интеграционный полёт не проверен.

Для отдельного legacy-интерфейса установите `requirements-legacy.txt`, запустите `python app.py` в отдельном окружении/порту. Аппаратный флаг `SWARM_ENABLE_REAL` оставляйте `0`. Наличие SITL-режима в старом мосте не определяет, является ли указанный endpoint симулятором; используйте выделенную лабораторную сеть и адрес локального SITL.

После подготовки ArduPilot по [официальной инструкции](https://docs.ardupilot.org/dev/docs/setting-up-sitl-on-linux.html), в его репозитории можно запустить:

```sh
./Tools/autotest/sim_vehicle.py -v ArduCopter --no-mavproxy
```

Официальная документация описывает TCP 5760 для подключения GCS без MAVProxy. Проверьте параметры выбранной версии и номера нескольких инстансов. В legacy-мосте endpoint для первого локального симулятора: `tcp:127.0.0.1:5760`. [Using SITL](https://docs.ardupilot.org/dev/docs/using-sitl-for-ardupilot-testing.html).

Для PX4 сначала настройте [официальную симуляцию](https://docs.px4.io/main/en/simulation/). Offboard требует непрерывного сигнала от внешнего контроллера, валидной навигации и правильных failsafe. Существование поля скоростей не заменяет эти условия. [PX4 Offboard](https://docs.px4.io/main/en/flight_modes_fw/offboard).

Дальнейший этап: read-only телеметрия → проверка преобразования координат и времени → setpoints в изолированном SITL → отключение ground/peer/интернета/GNSS и ошибки питания → независимые аварийные реакции → подтверждённый оператором аппаратный контур. Подключение реальных аппаратов из публичного веб-приложения отсутствует.
