# AGMEN: развёртывание на Amvera

Проверено по официальной документации 21 октября 2026. Доступ к вашему личному кабинету Amvera в этой сессии отсутствует; публичное приложение здесь не развёрнуто и HTTPS-адрес не выдумывается. Локальный продукт работает независимо от Amvera.

## 1. Подготовить GitHub

Используйте корень репозитория с `Dockerfile`, `amvera.yml`, `frontend/`, `agmen_api.py` и `edge/`. Внешняя папка, в которую распакован архив, в сборку не входит. Изменения подготовлены в `feature/agmen-platform-v3`; основная ветка не перезаписывается. После проверки PR слейте его или выберите эту ветку для отдельной демонстрации.

```sh
git clone https://github.com/mavrodi228-bot/swarm-density-control.git
cd swarm-density-control
git checkout feature/agmen-platform-v3
```

Перед публикацией проверьте отсутствие `.env`, `data/`, токенов и пользовательских миссий в коммите.

## 2. Создать проект

В кабинете Amvera создайте приложение и выберите регион, где находится постоянное хранилище. Начинайте с ресурсов, достаточных для загрузки CPU PyTorch; размер процесса и обучения проверяйте в мониторинге своего тарифа. Код ограничивает задания, но не может увеличить оплаченный RAM.

## 3. Подключить репозиторий

В настройках репозитория приложения используйте подключение внешнего GitHub. URL webhook и секрет берите из своего кабинета, задайте их в GitHub и включите SSL verification. Секрет не коммитьте. Точные названия полей могут зависеть от интерфейса кабинета; последовательность подключения описана в [официальном примере GitHub](https://docs.amvera.ru/general/examples/miniappex.html).

## 4–5. Выбрать Docker

Используются именно `Dockerfile` и `amvera.yml` этого репозитория. Amvera поддерживает Dockerfile; Docker Compose для этого развёртывания не используется. [Документация Docker](https://docs.amvera.ru/applications/configuration/docker.html).

```yaml
meta:
  environment: docker
  toolchain:
    name: docker
build:
  dockerfile: Dockerfile
  skip: false
run:
  containerPort: 7860
  persistenceMount: /data
```

Сначала Node собирает React, затем Python-образ получает готовую статику и CPU-бэкенд. На runtime Node не требуется. Это один fullstack-контейнер.

## 6. Порт

Приложение слушает `0.0.0.0:7860` внутри контейнера. Укажите `PORT=7860`, `HOST=0.0.0.0`; `run.containerPort` уже равен 7860. Прокси Amvera должен направлять веб-запросы в этот порт. [Сетевые настройки](https://docs.amvera.ru/applications/configuration/network.html).

## 7. Переменные окружения

| Переменная | Public demo | Research private |
|---|---|---|
| `AGMEN_PROFILE` | `public` | `private` |
| `AGMEN_DATA_DIR` | `/data` | `/data` |
| `HOST` / `PORT` | `0.0.0.0` / `7860` | То же |
| `AGMEN_ALLOWED_HOSTS` | Реальный hostname из кабинета без https:// | То же |
| `AGMEN_ALLOWED_ORIGINS` | `https://` + реальный hostname | То же |
| `AGMEN_API_TOKEN` | Не нужен | Секрет длиной минимум 24 символа |
| `AGMEN_MAX_RSS_MB` | `1536`, уменьшите под RAM тарифа | Под доступную RAM |
| `OMP_NUM_THREADS`, `MKL_NUM_THREADS`, `OPENBLAS_NUM_THREADS` | `2` | `2` |
| `SWARM_ENABLE_REAL` | `0` | `0` |

В private-профиле сервер откажется запускаться без достаточно длинного токена. Создайте его локально `python -c "import secrets; print(secrets.token_urlsafe(32))"`, сохраните как секрет сервиса, а затем введите в настройках приложения. Используется заголовок `X-AGMEN-Token`, не query string. Не размещайте секрет в скриншотах/исходниках.

## 8. Постоянное хранилище

Примонтируйте Data по `/data`; задайте **абсолютный** `AGMEN_DATA_DIR=/data`. В нём сохраняются миссии, эксперименты, обучение и EDGE. На каталог должен иметь право записи uid 10001, используемый образом. При permission denied проверьте права монтирования в сервисе; не отключайте сохранение как обход ошибки. `/app/data` и `/data` — разные каталоги. [Хранилище Amvera](https://docs.amvera.ru/applications/storage.html).

Используйте одну реплику: текущее файловое хранилище и очередь рассчитаны на один процесс. Настройте резервное копирование Data до обновлений.

## 9. Backend и frontend

Управляет `Dockerfile`: `npm ci`, `npm run build`, `pip install -r requirements-runtime.txt`, запуск `python launch_agmen.py --serve`. Frontend обращается к `/api` на том же домене; дополнительных CORS-доменов или второго проекта не нужно. В коде нет адреса localhost для production-запросов.

## 10. Миграции

SQL-базы и SQL-миграций в этой реализации нет. Создание каталогов и восстановление JSON выполняются при запуске. Задачи, прерванные перезапуском, отмечаются ошибкой; повторите запуск из интерфейса. Перед будущим изменением формата состояния делайте backup `/data` и реализуйте соответствующую миграцию.

## 11. Очередь и ресурсы

Симуляции используют встроенную очередь с одним worker и пределом три активных/ожидающих задания. Обучение работает в отдельном subprocess, один run на хранилище. Внешние Redis/Celery не требуются. Public-профиль отключает обучение. Для частного исследования выделите отдельный контейнер/тариф с достаточной памятью; режим распределённого ML-worker в этой версии не реализован.

Локальная проверка с жёсткими лимитами контейнера:

```sh
docker build -t agmen:local .
docker run --name agmen --cpus=2 --memory=2g -p 7860:7860 \
  -e AGMEN_PROFILE=public -e AGMEN_ALLOWED_HOSTS=localhost,127.0.0.1 \
  -v agmen-data:/data agmen:local
```

В Amvera предел ресурсов задавайте в настройках своего проекта. `AGMEN_MAX_RSS_MB` — прикладной порог, а не жёсткий OS sandbox.

## 12. Нейросетевые веса

Исходный `model_data/swarm_unet.pt` входит в образ. Checkpoint отсутствует или несовместим — нейросетевой режим отклоняется, математический доступен. Новые модели сохраняются в `/data/lab/runs/...`, выбираются в AI Laboratory после синтетической проверки. Не загружайте произвольный Python-код или непроверенные pickle-файлы. Raspberry Pi/Jetson — отдельная установка, см. `AGMEN_EDGE.md`.

## 13–14. HTTPS и публичная ссылка

После успешного запуска добавьте/включите внешний домен приложения в разделе доменов Amvera и HTTPS по инструкции сервиса. Реальный hostname внесите в `AGMEN_ALLOWED_HOSTS`, а полный HTTPS origin — в `AGMEN_ALLOWED_ORIGINS`, перезапустите контейнер. Явное разрешение HTTPS origin нужно при TLS termination на reverse proxy: внутренний HTTP и внешний HTTPS имеют разные origin. Локальный host healthcheck остаётся разрешённым. Ссылку копируйте из кабинета; шаблон в документации не является адресом развёрнутого AGMEN.

```sh
curl --fail https://YOUR_ACTUAL_DOMAIN/api/health
```

Замените `YOUR_ACTUAL_DOMAIN` адресом своего проекта. В ответе нужны `app: AGMEN`, `status: ok`, `simulation_only: true`. Затем откройте `/` и создайте миссию. [Официальная настройка сети и доменов](https://docs.amvera.ru/applications/configuration/network.html).

## 15–16. Логи и диагностика

Смотрите отдельно логи сборки и приложения в кабинете. `PYTHONUNBUFFERED=1` уже задан. Ошибка `npm ci` — проверить lock-файл; отсутствуют веса — проверить `model_data`; 502 — host/port; 400 Invalid host — `AGMEN_ALLOWED_HOSTS`; 401 — токен; 403 — public запрет или Origin; 429 — очередь занята; 503 — runtime/RSS; ошибка записи — `/data` и права. ML worker хранит локальный лог внутри каталога run.

Для своей Docker-проверки: `docker logs agmen`, `docker inspect agmen`, `curl --fail http://127.0.0.1:7860/api/health`.

## 17. Обновления

После проверки PR обновляйте только выбранную ветку. Webhook запускает новую сборку; проверьте логи и health. Не делайте force push в main. До обновления остановите активные эксперименты и дождитесь checkpoint обучения.

## 18. Rollback

Для Docker используйте предыдущий известный коммит и повторную сборку или версионированный образ. Сделайте `git revert` неисправного изменения в выбранной ветке и push. Функция Amvera «Контроль версий» имеет ограничения для Dockerfile; не рассчитывайте на неё как на универсальный механизм rollback. [Официальные ограничения](https://docs.amvera.ru/applications/version-control.html). Возврат кода не откатывает Data; при изменении формата требуется совместимый backup.

## 19. Приватные разделы

Research: `AGMEN_PROFILE=private`, сильный токен и HTTPS; для нескольких операторов поставьте внешний identity-aware reverse proxy. Реализация не содержит пользователей/ролей/MFA. Public: нет обучения и физических команд; миссии общие, поэтому используйте только демонстрационные данные. EDGE-управление в публичном интерфейсе относится к виртуальным устройствам.

## 20. Проверка с ПК и телефона

Откройте полученный HTTPS URL, создайте 10 аппаратов/baseline, выполните расчёт, воспроизведите траектории и скачайте CSV. Переключите режим интерфейса. Проверьте EDGE: подготовить пакет, загрузить в виртуальное устройство, отключить интернет в сценарии, выполнить локальные шаги, восстановить связь и синхронизировать журнал. При radio loss последняя подтверждённая координата должна оставаться помеченной как устаревшая. Повторите на телефоне и проверьте прокрутку/доступность управления.

Amvera обслуживает демонстрацию и аналитику. Исполняемый `python -m edge` хранится и запускается на локальной машине; его цикл не зависит от доступности Amvera. Для настоящих полётных испытаний остаются SITL, калибровка карты и навигации, независимые failsafe и аппаратная квалификация.
