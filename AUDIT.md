# AGMEN: аудит исходного архива

Дата: 21 октября 2026. Исходная версия: `04a53f685abfc3f47ffc46e8e0e88e6aff53a101`.

## Что обнаружено

Архив содержал корень репозитория во вложенной папке `swarm-density-control-main/`, без `.git`. История получена из исходного публичного репозитория; разработка ведётся в отдельной ветке `feature/agmen-platform-v3`.

| Компонент | Состояние исходной версии |
|---|---|
| `swarm_core.py` | Рабочее уравнение непрерывности на сетке, спектральное решение Пуассона DCT, потоки через грани, маски препятствий, нормировка плотности, метрики |
| `fleet_core.py` | Рабочая дискретная группа: Hungarian assignment, целевые слоты, поле плотности, ограничение скорости/ускорения, отталкивание, обход прямоугольников, траектории. Исходный публичный runner ограничен 100 аппаратами |
| `model.py` | Небольшая U-Net, 3 входных канала и 2 выходных потока. При отсутствии файла весов исходная функция молча возвращала случайно инициализированную модель |
| `model_data/swarm_unet.pt` | Есть веса (477429 байт). Формат совместим с исходной архитектурой. Это исследовательская модель, не аттестованный полётный контроллер |
| `model_data/training_history.json` | История пяти эпох с train loss и LR. Нет исходных validation/test результатов, версии датасета или доказательства устойчивости |
| `train_model.py` | Рабочий CLI обучения на синтетических примерах эксперта; отсутствовали интерфейс, отдельный worker, остановка/возобновление, независимые validation/test |
| `app.py` | Gradio, глобальные LAST_* объекты общие для пользователей. Модель загружалась при импорте. Смешаны симуляция и интерфейс MAVLink |
| `mission_scenarios.py` | Офлайн исследовательская имитация полезной нагрузки после движения: аппараты стоят в конечных слотах, «кадры» и покрытие условные. Это честно описано в исходном docstring |
| `analytics.py`, `fleet_analytics.py` | Рабочие matplotlib-графики и экспорты. Benchmark плотности на фиксированной сетке не измеряет физический полёт миллиона отдельных аппаратов |
| `mavlink_bridge.py`, `real_mission.py` | Реальные MAVLink-интерфейсы с флагом SWARM_ENABLE_REAL и подтверждением оператора. Наличие кода не доказывает испытания с PX4/ArduPilot |
| Исходные тесты | Сохранение массы/уменьшение MAE, запуск группы, проверка числа назначений; сценарии проверялись отдельным main, не pytest discovery |
| Развёртывание | Python/Gradio Amvera-конфигурация и bat/sh. Не было Dockerfile, React, API, auth, очереди, сохранения сессий или EDGE |

## Стабилизация и решения

- На компьютере Python по умолчанию — 3.14. Для воспроизводимости CPU PyTorch 2.10 используется отдельное окружение Python 3.12; системные пакеты не изменяются.
- `model.load_model` теперь отклоняет отсутствующие веса. Новый API не подменяет нейросетевой режим baseline при недоступной модели.
- Исходные `swarm_core.py`, `fleet_core.py`, датасет и научные материалы сохранены. Новый `agmen_simulation.py` использует функции существующего контроллера и снимает ограничение оболочки на 100 аппаратов, сохраняя предел API 500.
- Полевое управление в исходном fleet-контроллере смешано с назначением слотов (0.35/0.65). Сравнение контроллеров в новом интерфейсе использует эту общую систему; это не сравнение чистых независимых полевых алгоритмов.
- Нормировка после отсечения отрицательных плотностей — численная стабилизация исходного метода. Сохранение суммы 1 после нормировки не доказывает точную физическую консервативность исходной PDE на каждом шаге.
- Новый API не импортирует MAVLink и не предоставляет физических команд. Старый `app.py` остаётся отдельным legacy-инструментом.
- Географических подложек, координат origin и полётных карт в исходном архиве нет. Новая карта — локальная плоскость с задаваемыми размерами (по умолчанию 80×60 м), работает без сети. Пользователь может загрузить PNG/JPEG/WEBP и подтвердить запреты по результатам эвристического анализа либо нарисовать их. Метры задаются вручную; географическая привязка не выводится из изображения.
- Пропавшая телеметрия, модельное истинное состояние и прогноз различаются в EDGE. Локальное исполнение не предполагает знания остальных аппаратов при недоступном peer-канале.

## Границы проверки

Автотесты и интеграционные прогоны выполняются на локальной симуляции; фактические результаты перечислены в `IMPLEMENTATION_REPORT.md`. Нет подключённого автопилота, Raspberry Pi, Jetson или аккаунта Amvera. Успешная симуляция не подтверждает готовность к полётным испытаниям. HTTP token — ограниченная защита исследовательского сервера; полноценные учётные записи, роли и аудит доступа требуют отдельной инфраструктуры.
