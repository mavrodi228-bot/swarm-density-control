# AGMEN EDGE: автономный локальный исполнитель

AGMEN Ground Station готовит автономный пакет. `python -m edge` загружает проверенный пакет, вычисляет управляющий поток и интегрирует движение виртуального аппарата без HTTP, интернета или доступа к наземному серверу. Это работающий отдельный исполняемый модуль для плоской симуляции. Он не отправляет команды автопилоту.

## Два уровня

Ground Station хранит конфигурацию группы и начальную плотность, распределяет слоты исходным алгоритмом и формирует пакет отдельного аппарата. Веб-панель предоставляет виртуальные бортовые компьютеры, переключатели каналов и синхронизацию.

EDGE хранит пакет и собственное состояние на диске, использует `swarm_core.expert_flux`, `model.predict_flux` при наличии модели и исходные функции маршрутизации/выборки поля из `fleet_core`. Независимый режим использует начальную групповую плотность, предрассчитанное поле и собственный назначенный слот. Это фиксированный план из доступных до отключения данных; он не знает текущих позиций остальных аппаратов.

В peer-режиме разрешён локальный перерасчёт поля только из собственной позиции и явно полученных свежих наблюдений. При отключённом peer-канале эти данные не используются. Новый централизованный оптимизатор с доступом к скрытому полному состоянию вместо автономии не подставляется.

## Mission Package Builder

В разделе **AGMEN EDGE CONTROL** выберите завершённую миссию, аппарат, политику и координацию. Нажмите подготовку пакета, скачайте ZIP, затем загрузите его в виртуальное устройство.

Архив содержит:

- `manifest.json`: схема версии 1, идентификатор по содержимому, mission/drone id, версия контроллера, SHA256 каждого файла.
- `mission.json`: назначенный слот/зона, начальная и домашняя позиции, маршрут, скорость/ускорение/высота, границы времени, резерв батареи, критерий прибытия, policy, параметры контроллера и журнала.
- `map.json`: размеры локальной области в метрах, маска и прямоугольники препятствий; для своей территории также `map_id`, снимок метаданных и подтверждённые фигуры. **Это локальные метры; geographic_origin отсутствует.** Географическая привязка не выдумана.
- `fields.json`: исходная и целевая плотности, управляющие потоки.
- `model.json`: для neural/hybrid безопасное числовое представление весов SwarmUNet с формой тензоров и версией; в baseline отсутствует.

Загрузчик не извлекает произвольные пути, не запускает код из ZIP и не использует pickle. Проверяет allowlist имён, отсутствие дублей, размер архива/распакованных данных, схему, конечность чисел, геометрию и хеши. При повреждении карты или пакета запуск отклоняется. SHA256 проверяет целостность; **это не криптографическая подпись доверенного оператора**. Для реального борта необходимы подпись, управление ключами, secure update и защищённое хранилище.

## Своя территория в автономном пакете

В Mission Control можно загрузить PNG/JPEG/WEBP до 4 МиБ, задать ширину и высоту участка в метрах и нарисовать прямоугольные, круглые или многоугольные запреты. Анализ `dark` / `water` / `contrast` выделяет кандидатов по цвету и контрасту; они применяются только после подтверждения оператором. Подложки сохраняются в `data/maps/`, черновик карты и фигур — в браузере, а завершённый расчёт сохраняет снимок территории и масштаба. По умолчанию поле равно 80×60 м; пользовательские размеры также передаются в EDGE.

Подтверждённые фигуры консервативно покрываются ячейками сетки 24×24. Эта же маска и её прямоугольные границы входят в пакет; симулятор и EDGE отклоняют шаг, если любой участок отрезка движения пересекает запрет. При необходимости целевые слоты переносятся в ближайшие свободные ячейки, число переносов записывается в `restriction_policy`. Это ограничение движения плоской модели, без гарантии достижимости цели или разделения аппаратов.

Пакет фиксирует рассчитанные геометрию и масштаб. Изменение карты или её калибровки в Ground Station не меняет уже подготовленный архив: нужно пересчитать миссию и создать пакет заново. Исходное растровое изображение в ZIP не включается; автономный исполнитель использует сохранённые маску, фигуры и поля без загрузки изображения с сервера. Географическая привязка и GPS из пользовательской картинки не выводятся.

**Очистить зоны** и **Новая карта** меняют текущий черновик Ground Station, сохраняя архив ранее созданных пакетов. Для этапа на подробной карте пакет фиксирует его физические координаты, унаследованные запреты, исходный идентификатор аппарата, начальные скорость и заряд. Привязка второго участка задаётся оператором как начало координат в метрах первой карты с масштабом 1:1; изображение не создаёт GPS-координаты и не меняет положение аппарата автоматически.

## Ожидание прибытия

Для новых миссий Ground Station по умолчанию ждёт фактического прибытия всей группы. Номинальное число шагов — минимальный горизонт с `dt=0.2`, после которого движущиеся групповые цели фиксируются и включается терминальное наведение. Пакет отдельного EDGE-аппарата содержит фиксированный локальный слот; он не воспроизводит неизвестные движения всей группы.

При `completion.wait_for_arrival=true` поле `completion.minimum_steps` хранит номинальный горизонт, а `limits.max_steps` — полный вычислительный бюджет из конфигурации миссии, обычно до 1200 шагов для local/private и до 600 для public. После минимального горизонта локальный исполнитель использует наведение на слот с обходом препятствий. Задача своего аппарата завершается по фактическому приближению к сохранённому слоту в пределах `arrival_tolerance_m` (в текущем пакете 1 м) и после минимального горизонта. Это не подтверждение прибытия всех аппаратов: групповой критерий отдельно измеряет наземная симуляция.

Если бюджет закончился до прибытия, EDGE переходит в `awaiting_extension`, удерживает положение и оставляет задачу незавершённой. Повторный вызов локального цикла или восстановление радио не увеличивают сохранённый бюджет. Наземное **Продолжить до цели** создаёт новый вычислительный отрезок из последнего состояния группы; для его автономного выполнения требуется новый пакет. Сохранённое состояние одного изолированного EDGE-аппарата не выдаётся за подтверждённое состояние всей группы. В legacy-пакетах без ожидания номинальный лимит и прежняя политика возврата сохраняются.

## Независимый запуск без сервера

Из корня проекта, с установленными numpy/scipy/pandas:

```powershell
.venv\Scripts\python -m edge validate examples/edge/mission-continue.zip
.venv\Scripts\python -m edge run examples/edge/mission-continue.zip --state data/device-demo --steps 20 --offline
.venv\Scripts\python -m edge run examples/edge/mission-continue.zip --state data/device-demo --steps 20 --offline --link-lost
```

Повторный вызов с тем же `--state` восстанавливает позицию, батарею, шаг и журнал, затем продолжает. Сервер `agmen_api` при этом может быть остановлен. `--offline` выключает интернет; `--link-lost` отдельно выключает наземное и межаппаратное радио. Состояние пишется атомарно в `state.json`, журнал в `journal.jsonl`.

Для neural/hybrid необходим совместимый локальный PyTorch. Baseline не импортирует torch. Готовые примеры и реальные результаты сравнения создаются командой `python scripts/create_edge_examples.py`.

## Каналы и политики

| Условие | Поведение модели |
|---|---|
| ONLINE | Интернет и наземное радио доступны; прямые подтверждения модельной телеметрии |
| OFFLINE | Интернет недоступен; предзагруженный локальный план исполняется; при доступном радио наземная телеметрия продолжает поступать |
| LINK LOST | Наземное и peer-радио потеряны; действует загруженная policy, скрытые соседние состояния не читаются |
| `hold` | При потере наземного радио аппарат удерживает текущую позицию |
| `return` | При потере радио следует к сохранённой домашней позиции через исходный обход препятствий |
| `continue` | Исполняет заранее назначенный локальный план; нет гарантии межаппаратного разделения без наблюдений |
| Недостоверная навигация / GNSS | Локальная остановка даже при разрешённом continue |
| Низкая батарея | Возврат; при исчерпании — остановка модели |
| Бюджет исчерпан, `wait_for_arrival=true` | `awaiting_extension`: удержание; задача остаётся незавершённой |
| Лимит legacy-пакета без ожидания | Возврат; прибытие домой завершается статусом `returned` |

Остановка здесь мгновенная модельная failsafe, а не реалистичная динамика торможения квадрокоптера. Высота постоянная, геозона плоская; нет GNSS/IMU fusion и аттестованного energy reserve.

## Телеметрия, прогноз, синхронизация

При потере радио последняя подтверждённая позиция замораживается. Возраст считается в секундах симуляции. Отдельный прогноз экстраполирует **последнюю подтверждённую** позицию/скорость; он имеет растущую неопределённость и не гарантирует обход препятствий. Истинное модельное состояние доступно для исследования, но не выдаётся за полученную с борта координату.

При восстановлении наземного радио локальные журналы синхронизируются в виртуальную Ground Station; интернет для прямого радиоканала не нужен. API сохраняет отдельную квитанцию и копию записей в `data/edge/ground_sync/<device-id>.json`, выполняет дедупликацию по номеру записи. Можно вручную вызвать `/api/edge/devices/{id}/sync`, скачать ground journal через `/api/edge/devices/{id}/journal`. Реального сетевого протокола передачи на Raspberry Pi в этой версии нет: транспорт в веб-панели симулируется; сам исполнитель независим от него.

Журнал и история ограничены по размеру. Это ротация, а не бесконечный архив полётных данных. Порог arrival и progress proxy не являются измеренным охватом территории. Локальная distribution_mae относится к собственной позиции и наблюдаемым соседям, а не к неизвестной полной группе.

## Raspberry Pi / Linux ARM64

Архитектура не требует x86, GUI или браузера на устройстве. На 64-битном Linux с совместимым Python и доступными numpy/scipy/pandas:

```sh
python3 -m venv .venv-edge
.venv-edge/bin/python -m pip install numpy scipy pandas
.venv-edge/bin/python -m edge validate examples/edge/mission-continue.zip
.venv-edge/bin/python -m edge run examples/edge/mission-continue.zip --state ./device-state --steps 20 --offline
```

Скопируйте проект и пакет на устройство заранее. Для постоянной службы добавьте собственный supervisor/systemd с отдельным пользователем, правами записи только в каталог состояния и аппаратным watchdog. Частота записи этой исследовательской версии рассчитана на симуляцию; перед microSD-эксплуатацией настройте долговечность и период checkpoint. Фактическая производительность Raspberry Pi здесь не измерялась.

## NVIDIA Jetson

Baseline запускается теми же командами. Для neural/hybrid используйте PyTorch, совместимый с конкретными JetPack, Python, CUDA и архитектурой устройства; Windows/x86 wheel `torch==2.10.0+cpu` из полного ground-runtime на ARM устанавливать не следует. Проверяйте совместимость по [NVIDIA PyTorch for Jetson](https://docs.nvidia.com/deeplearning/frameworks/install-pytorch-jetson-platform/index.html). GPU в текущем EDGE runtime автоматически не включается: inference выполняется CPU, аппаратное ускорение требует отдельной проверки. Испытаний Jetson в этой сессии нет.

## Отдельный Docker

```sh
docker build -f Dockerfile.edge -t agmen-edge:local .
docker run --rm --network none --cpus=1 --memory=768m \
  -v "$PWD/examples/edge:/packages:ro" -v agmen-edge-state:/state \
  agmen-edge:local run /packages/mission-continue.zip --state /state --steps 20 --offline
```

Этот образ содержит baseline-зависимости и не содержит веб-сервер или PyTorch. Для neural-пакетов нужна отдельная совместимая сборка. Образ использует multi-arch Python base, но ARM-сборка и запуск контейнера в этой Windows-сессии не выполнялись.

## Проверки и границы аппаратной готовности

Тесты проверяют отключение интернета до/во время миссии, запрет socket/DNS, равенство online/offline траекторий при одном независимом плане, radio/peer loss, политики, локальный журнал, восстановление и ground-sync, низкую батарею, недостоверную навигацию, повреждение/отсутствие карты и перезапуск CLI. Итоговые числа — в `IMPLEMENTATION_REPORT.md`.

MAVLink-модули исходного проекта сохранены. Новый EDGE **не подключён** к физическим аппаратам и не выдаёт MAVLink setpoints. До испытаний нужны реальная географическая привязка, сенсорная навигация, проверенный onboard transport, подпись пакетов, watchdog, аппаратный geofence/RTL/kill, испытания отказов в PX4/ArduPilot SITL и затем квалификация в изолированной среде. Ни public Amvera, ни локальный UI не включают полётные команды.
