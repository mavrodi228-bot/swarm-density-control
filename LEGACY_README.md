# Swarm Density Control GCS

Исследовательский симулятор и наземная станция верхнеуровневого управления группой **1–100 мультироторных БПЛА** в горизонтальной плоскости.

## Что изменено по сравнению с первой версией

Первая версия работала только с полем плотности `ρ(x,y,t)` и виртуально большими роями. Текущая версия добавляет практический слой, который переводит распределённое управление в команды отдельным аппаратам:

`оператор → целевое распределение → ρ(x,y) → поле J/v → дискретные целевые места → safety layer → vx/vy каждому БПЛА → MAVLink`.

В приложении теперь четыре вкладки:

1. **Симулятор миссии** — 1–100 отдельных аппаратов, взлёт, горизонтальное распределение, посадка, препятствия, ветер, ошибки положения, межбортовое разведение.
2. **Реальные БПЛА / SITL** — MAVLink endpoints, телеметрия, ARM/TAKEOFF/HOLD/LAND и запуск того же группового контроллера на подключённом флоте.
3. **Плотностная лаборатория** — исходная математическая модель с U-Net, математическим эталоном и гибридным режимом.
4. **Экспорт и документация** — CSV/JSON/NPZ результатов и индивидуальных команд.

## Ограничение задачи

Исследуемая модель является **двумерной**. Полёт разбит на этапы:

1. `TAKEOFF` — набор заданной рабочей высоты `H`;
2. `PLANAR` — групповое управление только по `X,Y` при `z≈H=const`;
3. `LANDING` — отдельная команда снижения.

Поэтому высотный обход препятствий, совместное изменение эшелона и полноценное 3D-планирование в эту работу не входят.

## Целевое распределение

Оператор задаёт таблицу вида:

| Точка | X, м | Y, м | БПЛА | Радиус, м |
|---|---:|---:|---:|---:|
| A | 60 | 15 | 1 | 2 |
| B | 60 | 43 | 9 | 7 |

Для десяти аппаратов это означает: **1 БПЛА в области A и 9 БПЛА в области B**. Из этих данных строится целевая плотность, а также десять дискретных целевых мест. Венгерский алгоритм назначает аппаратам места с минимизацией суммарного начального перемещения.

## Контроллер

В режиме `Density control` команды конкретному аппарату формируются из нескольких слоёв:

- макроскопическое поле плотностного контроллера;
- притяжение к назначенному дискретному месту внутри заданного распределения;
- обход препятствий через промежуточные путевые точки;
- локальное межбортовое разведение;
- ограничение скорости и ускорения.

Плотностное поле можно получать тремя способами:

- `Математический эталон`;
- `Нейросеть` (U-Net);
- `Гибрид 70/30` — 70% нейросетевого и 30% математического поля.

Отдельно реализован `Leader–Follower` для сравнительного эксперимента.

## SITL / реальный MAVLink

В таблице подключений указывается отдельный endpoint для каждого аппарата, например:

```text
UAV-01   udp:127.0.0.1:14550
UAV-02   udp:127.0.0.1:14560
```

Поддерживаемая логика обмена использует MAVLink telemetry и `SET_POSITION_TARGET_LOCAL_NED` для индивидуальных горизонтальных velocity setpoints.

### Защита реального режима

По умолчанию реальные управляющие команды **заблокированы**. Для их разрешения нужны одновременно:

1. режим `REAL`;
2. подтверждение оператора в интерфейсе;
3. переменная окружения:

```bash
# Windows PowerShell
$env:SWARM_ENABLE_REAL="1"

# Linux/macOS
export SWARM_ENABLE_REAL=1
```

Это сделано специально, чтобы случайный запуск интерфейса не приводил к ARM/TAKEOFF физического аппарата.

Перед реальным полётом требуется отдельная проверка параметров конкретного автопилота, геозоны, failsafe, радиоканала, GNSS/локализации, направления осей и аварийного ручного перехвата. Код является исследовательским прототипом с production-oriented архитектурой, но не сертифицированным полётным ПО.

## Файлы

- `app.py` — интерфейс GCS.
- `fleet_core.py` — дискретный симулятор 1–100 БПЛА и перевод поля в индивидуальные команды.
- `fleet_analytics.py` — графики, экспорт, benchmark.
- `mavlink_bridge.py` — телеметрия и MAVLink команды PX4/ArduPilot.
- `real_mission.py` — замкнутый real/SITL контур `telemetry → planner → setpoints`.
- `swarm_core.py` — математическая модель плотности.
- `model.py` — U-Net.
- `report_fleet_experiment.py` — воспроизводимые эксперименты и рисунки для статьи.
- `test_fleet_core.py` — базовые автоматические тесты.

## Обновление по замечаниям ментора (15.10.2026)

### Новая вкладка «Сценарии после прибытия»

1. На вкладке симулятора включите «Продолжить задачами в зонах (не выполнять посадку)».
2. Запустите распределение аппаратов до целевых точек.
3. Перейдите во вкладку «Сценарии после прибытия» и нажмите «Загрузить точки последней миссии».
4. Для каждой точки задайте тип гражданской задачи: **наблюдение, виртуальная площадная съёмка, виртуальный периметр, ожидание**.
5. При необходимости загрузите PNG/JPG/WEBP изображение карты (исключительно фон в локальной плоскости; **GPS-привязки нет**).
6. Можете включить **симуляцию** потери связи: HOLD / RETURN_REQUEST / LAND_REQUEST (только записи, без реальных команд).
7. После запуска просмотрите визуализацию, виртуальное количество кадров и журнал событий; экспортируйте JSON/CSV.

**Важно:** сейчас задачи сенсоров, охват секторов и потеря связи лишь **исследовательская модель**. Здесь не реализованы геопривязанная аэрофотосъёмка, камера БПЛА, маршруты покрытия области в физическом пространстве, реальный бортовой offline-план, автономная навигация без GNSS. Пакет `scenario_simulation.json` специально помечен `RESEARCH_SIMULATION_NOT_FOR_FLIGHT` и не пригоден для загрузки в автопилот. Команды реальных аппаратов из этого модуля **не выдаются**.

Внешний контур MAVLink остался из исходной версии и по-прежнему физически небезопасен без отдельной валидации: на публичном Amvera не включайте `SWARM_ENABLE_REAL`.
